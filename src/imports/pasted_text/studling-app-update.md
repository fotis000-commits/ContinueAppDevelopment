# 13. COUPON REDEMPTION BEHAVIOR

Implement a complete redemption flow.

### Reward Eligibility

Each reward should have:

* Reward name
* Description
* Required Credits
* Reward type
* Availability
* Expiration information if applicable
* Demo/Prototype label

A student can redeem a reward only if they have enough Credits.

If they do not have enough Credits:

* Disable the redemption button
* Show how many more Credits they need
* Do not deduct anything

Example:

**Not enough Credits**

"You need 250 more Credits to redeem this reward."

Provide a way to discover legitimate activities that can earn Credits.

---

### Redemption Confirmation

When the student chooses to redeem a reward, show a confirmation screen.

Display:

* Reward name
* Credits required
* Current balance
* Balance after redemption
* Confirm button
* Cancel button

Do NOT deduct Credits until the student confirms.

---

### Successful Redemption

After confirmation:

1. Verify the student's current Credits balance using trusted database/server logic.
2. Verify the reward is still available.
3. Verify the student has enough Credits.
4. Deduct the required Credits.
5. Create a unique redemption record.
6. Generate a unique coupon/reward code.
7. Add the reward to My Rewards.
8. Add the transaction to Credits History.
9. Display a success confirmation.

Example:

**Reward Unlocked!**

**Coupon Code: STUDLING-DEMO-XXXX**

Clearly mark prototype coupons as Demo Coupons.
